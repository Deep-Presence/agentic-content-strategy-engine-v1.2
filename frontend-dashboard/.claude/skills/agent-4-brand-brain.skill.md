> **Wait for Agent 0 to complete.** Run `git pull` before starting. You depend on the design system, API client, types, and layout shell.

## Your Mission

Build the **Brand Brain** — the knowledge management hub where companies configure their brand identity, manage projects (product-level knowledge bases), personas, style guides, and trigger research pipelines. This is where the AI agents get their context — everything the system knows about the company lives here.

**Key Insight:** The Research Pipeline (company context → personas → style guide) lives INSIDE Brand Brain, not as a separate section. When a user wants to generate personas or a style guide, they do it within Brand Brain, and the HITL approval flow happens inline.

**Knowledge Completeness Score:**
Simple percentage based on how many of these items exist:
- Company Context (25%)
- ICP Persona (25%)
- Style Guide (25%)
- At least 1 additional knowledge doc (25%)

Each shows ✅ (generated & approved), ⚠️ (draft exists), or ❌ (not started).

**Data Sources:**
- `GET /api/v1/artifacts/companies` — List companies
- `GET /api/v1/artifacts/company_context/{slug}` — Check if company context exists
- `GET /api/v1/artifacts/personas/{slug}` — Check if personas exist
- `GET /api/v1/artifacts/style_guides/{slug}` — Check if style guide exists
- `GET /api/v1/tasks?pipeline=research` — Recent research runs

**"Generate via Research" button flow:**
1. Click → shows inline form: Company Name, Domain, Seed URLs, Max Personas
2. Submit → calls `POST /api/v1/research/start` with `stages: ['persona']` (or full pipeline)
3. Inline progress bar shows SSE events: "Researching persona..." → "Draft ready"
4. When `persona_draft` event arrives → show draft content inline with HITL buttons
5. Approve/Revise/Reject inline (calls `POST /api/v1/research/{run_id}/approve`)
6. On approve → persona card updates to show final content

**Persona Detail View (expand or modal):**
Full rendered markdown content of the persona. Read-only unless user clicks "Edit".

## Research Pipeline Integration

The research pipeline trigger and HITL flow is the key UX innovation here — it happens INSIDE Brand Brain, not in a separate section.

### Research Trigger Component

**`brand-brain/components/research-trigger.tsx`:**

```typescript
interface ResearchTriggerProps {
  mode: 'full' | 'company' | 'persona' | 'style';
  companySlug: string;
  onComplete: () => void;  // Callback to refresh parent data
}
```

**Renders:**
1. A primary button: "🔬 Generate {mode}" or "🔬 Run Full Research"
2. On click → expands to show a form:
   - Company Name (pre-filled from current company)
   - Domain (pre-filled)
   - Seed URLs (editable list)
   - Stages: pre-selected based on `mode`, or all three for 'full'
   - Auto-approve: checkbox (default: false)
3. Submit → `POST /api/v1/research/start`
4. Form collapses → progress indicator appears

### Research Progress Component

**`brand-brain/components/research-progress.tsx`:**

Inline progress showing the research pipeline's SSE events:

```
┌──────────────────────────────────────────────────────────────┐
│ 🔬 Research Pipeline Running                                  │
│                                                                │
│ ✅ Company Context: Generated                                 │
│ 🔄 Persona Research: In progress...                          │
│ ○  Style Guide: Waiting                                       │
│                                                                │
│ [Cancel]                                                       │
└──────────────────────────────────────────────────────────────┘
```

Connects to `GET /api/v1/tasks/{taskId}/events` via SSE.

### Research Approval Inline Component

**`brand-brain/components/research-approval-inline.tsx`:**

When a research stage produces a draft and is waiting for approval (`pending_approval` status):

```
┌──────────────────────────────────────────────────────────────┐
│ 📋 Persona Draft Ready for Review                             │
│                                                                │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ (Rendered markdown preview of the persona draft)          │ │
│ │                                                            │ │
│ │ "The ideal customer for Webflow is a Senior Finance..."   │ │
│ │ ...                                                        │ │
│ │ (scrollable, max-height: 400px)                           │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                                │
│ [✓ Approve] [✎ Revise — add note] [✕ Reject]                │
│                                                                │
│ Revision note: [                                    ]         │
│ (shown when "Revise" is clicked)                               │
└──────────────────────────────────────────────────────────────┘
```

**Actions:**
- **Approve:** `POST /api/v1/research/{run_id}/approve` with `{ decision: "approve" }`
  - Pipeline continues to next stage
  - Update UI: mark stage as ✅, move to next
- **Revise:** Shows text input for revision note, then sends `{ decision: "revise", revision_note: "..." }`
  - Agent revises → new draft → approval UI shows again
- **Reject:** `POST /api/v1/research/{run_id}/approve` with `{ decision: "reject" }`
  - Stage is skipped (for persona/style) or pipeline stops (for company context)

### Artifact Viewer Component

**`brand-brain/components/artifact-viewer.tsx`:**

Renders markdown content from artifacts in a clean, styled view.

```typescript
interface ArtifactViewerProps {
  content: string;          // Markdown string
  title: string;
  type: 'company_context' | 'persona' | 'style_guide';
  editable?: boolean;
  onSave?: (newContent: string) => void;
}
```

Uses `react-markdown` with `remark-gfm` and `rehype-sanitize` to render markdown. Styled to match the brand typography (Lora for body text, Source Serif for headings within the content).

## Zustand Store

**`src/stores/brand-store.ts`:**
```typescript
interface BrandState {
  // Company context
  companyContext: string | null;
  companyContextStatus: 'none' | 'draft' | 'approved';

  // Personas
  personas: Persona[];

  // Style guide
  styleGuide: string | null;
  styleGuideStatus: 'none' | 'draft' | 'approved';

  // Knowledge docs
  knowledgeDocs: KnowledgeDoc[];

  // Projects
  projects: Project[];

  // Research pipeline state
  activeResearchRunId: string | null;
  activeResearchStatus: TaskStatus | null;
  activeResearchStage: ResearchStage | null;
  approvalPayload: Record<string, any> | null;

  // Actions
  setCompanyContext: (content: string, status: 'draft' | 'approved') => void;
  setPersonas: (personas: Persona[]) => void;
  addPersona: (persona: Persona) => void;
  setStyleGuide: (content: string, status: 'draft' | 'approved') => void;
  setKnowledgeDocs: (docs: KnowledgeDoc[]) => void;
  addKnowledgeDoc: (doc: KnowledgeDoc) => void;
  removeKnowledgeDoc: (id: string) => void;
  setProjects: (projects: Project[]) => void;
  addProject: (project: Project) => void;
  setResearchRun: (runId: string, status: TaskStatus, stage: ResearchStage) => void;
  setApprovalPayload: (payload: Record<string, any> | null) => void;
  clearResearchRun: () => void;
}
```

## API Endpoints You Use

| Endpoint | Where Used |
|----------|-----------|
| `POST /api/v1/research/start` | Trigger research pipeline |
| `GET /api/v1/research/{run_id}/status` | Poll research status |
| `POST /api/v1/research/{run_id}/approve` | HITL approval |
| `GET /api/v1/tasks/{task_id}/events` | SSE progress stream |
| `GET /api/v1/artifacts/companies` | List companies |
| `GET /api/v1/artifacts/company_context/{slug}` | List company context files |
| `GET /api/v1/artifacts/company_context/{slug}/{filename}` | Get company context content |
| `GET /api/v1/artifacts/personas/{slug}` | List persona files |
| `GET /api/v1/artifacts/personas/{slug}/{filename}` | Get persona content |
| `GET /api/v1/artifacts/style_guides/{slug}` | List style guide files |
| `GET /api/v1/artifacts/style_guides/{slug}/{filename}` | Get style guide content |
| `GET /api/v1/tasks?pipeline=research` | List research runs |
